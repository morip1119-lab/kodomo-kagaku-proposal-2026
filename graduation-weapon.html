YouTube案件管理シート
— 複数チャンネル運営の「散らかる面倒」を消す武器

YouTubeクライアントを複数抱える運営の現場で、打ち合わせ準備・宿題の抜け漏れ・登録者確認が毎回バラバラだった。 それを1画面に集約し、毎日の確認コストを下げる仕組みを作った。

02 · 解決する面倒・課題

Before（面倒）
  • 打ち合わせ前に、メモ・スプレッド・Studioを行き来する
  • 「前回何を決めたか」を探す時間が毎回かかる
  • 宿題が口頭で消え、1週間後に気づく
  • 登録者数の確認が手作業で、数字の鮮度がバラバラ
After（武器）
  • チャンネルを選ぶ → 履歴 → 決定事項 → ToDo が一直線
  • 期限切れToDoが一目で分かる
  • 登録者はAPIで毎日自動更新
  • 週次レポートで「止まっている案件」を見える化

使う場面：クライアント定例の前夜・当日、週初の進捗確認、チーム内の引き継ぎ。

03 · 作りたいと思った理由

YouTube運営は「企画が弱い」より先に、決めたことが実行されないで数字が落ちることが多い。 自分の仕事では、複数チャンネルの定例準備と宿題管理がボトルネックだった。 AIで企画を出す前に、運営の土台（進捗・議事・数字）を一つの武器にする必要があると感じた。

半年間で学んだ「面倒を分解して消す」「小さく作って使う」を、自分の本業にそのまま当てはめた。

04 · 工夫したポイント / 苦戦したポイント

工夫したこと
  • 3カラムUI：選ぶ→見る→動く、の導線を固定
  • 議事録からToDoを自動集約（7日未着手は期限切れ表示）
  • 登録者は YouTube Data API で毎日12時自動取得
  • file:// でも動くよう JSON + JS埋め込みで同期
  • 既存データに新チャンネルをマージ（リセット不要）
苦戦したこと
  • Studioの深い数字（維持率・流入）は OAuth が必要で、APIキーだけでは取れない
  • クライアントごとにオーナー認可が必要な壁
  • ローカル保存と自動取得の反映タイミング（キャッシュ・未保存）
  • 「全部自動化」より「まず毎日使う画面」を優先する判断

05 · 発表で見せること（6分用）

  1. 仕事の前提（60秒） — 複数YouTubeチャンネルを運営している
  2. 面倒（60秒） — 定例前の情報探し・宿題抜け・数字確認
  3. デモ（2分） — チャンネル選択 → 履歴 → ToDo → 登録者
  4. 仕組み（60秒） — API自動取得・週次レポート・今後Analytics
  5. 学び（60秒） — 小さく作って使い、止まる場所を潰した

個人名・機密は一般化して話す。クライアント固有の中身は深入りしない。
